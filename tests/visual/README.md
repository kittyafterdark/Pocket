Visual regression fixtures come from the actual frontend contract harness and tracker renderer, using controlled state, a fixed story clock, blocked external requests and Chromium. No live chat data or connections are exported.

`bun run test:launcher` runs an interactive controller fixture at 390px and 900px, including drawer search, shortcut/dock edits, save failures, close/reopen, reload persistence, keyboard dismissal, UI scales, and the canonical mobile safe-top contract. It also exercises screen dots, screen/folder removal without losing contents, named folders, live tracker widgets, missing trackers, and widget navigation/persistence. It writes captures to ignored `tmp/launcher` and uses the same Playwright installation as the visual runner. It also checks the App Store catalog, search-first layout, illustrated carousels with arrow and keyboard navigation, light/dark themes, installation filters, keyboard Get, Remove/reinstall persistence, featured-action scroll/focus preservation, nonzero page-scroll installs from the lower Socials section, delayed state/ack delivery, Available-filter retention, and failed-update recovery. This fixture never reads live extension storage.

`bun run test:socials` uses the real controller, SocialWorld, SocialDms, and SocialAutomation services with controlled model responses and localStorage fixtures. It checks sample posts/stories without persisting them, post discussions, threaded reply-backs, distinct quotes and comments, private Instagram inbox persistence, per-server Discord People banks, NPC Bank friends, bios/following, and all four Tumblr palettes. Photo checks cover Gallery, native uploads, generation, failure recovery, cancellation, and late results. Settings checks exercise the main feed Refresh action, Manual/After each turn/Automatic modes, timer intervals with an injected clock, duplicate-turn suppression, real feed photos, and reload persistence. They also check internal Back versus Pocket Home, app-specific comment composers below the original post, pinned Instagram DM input, Discord creation-to-server navigation, abstract avatars, and Tumblr palettes in settings. It also checks keyboard focus/dismissal, stable Refresh/Stop layout, midnight/porcelain themes, three UI scales, and canonical notched-mobile safe-top spacing at 390px and 900px. Captures go to ignored `tmp/socials`; no real chats, files, or live model connections are used.

`bun run test:message-continuity` uses the real controller with a controlled multi-day direct conversation, consumed handoff, and reply delivery. At 390px and 900px it checks story-day separators, presence/receipts, pinned force/Stop controls, response and cancellation focus, retained drafts and reading position, and that message reveals never scroll the outer phone or host page. It also checks a shared right edge for short outgoing bubbles, one pinned stripe per plan, stripe fit across UI sizes, keyboard review of proposed revisions, isolated Quickstart-card rendering, and removal of deleted/started plans from the upcoming strip. Captures are written to ignored `tmp/message-continuity`.

Run `bun run build` first, then `bun run test:visual`. Set `POCKET_PLAYWRIGHT_ROOT` to an existing Playwright installation if it is not locally available; the runner also looks for the sibling LumiTest diagnostics installation. Chromium must already be installed by that environment.

Baselines cover mobile and desktop home, Settings, device switcher, messaging, camera composition/review, tracker presentations, weather viewer and weekly forecast widgets, between-turn conversation connectors, scene message/group cards, and full-phone lock/chat/group/call states, including exact, approximate and untimed clocks. Hostile global selectors must leave isolated artifacts unchanged. A deliberate internal styling mutation must change the capture, proving the comparator is active.

An intentional design change can refresh baselines with `bun run test:visual:update`. Inspect the affected images before committing. A normal run never changes expected images; failures write actual images to ignored `tmp/visual`. Browser version and platform are recorded to prevent silently comparing incompatible rendering environments. These checks supplement live Lumi smoke tests; they do not replace dock lifecycle, keyboard, handset-scale or mobile fullscreen checks.

Voice messages add a `chat-voice` fixture at both viewport widths, checking that the transcript remains readable without playback. Use `bun run test:visual --case=chat-voice` for a focused check. Playback, browser errors, host TTS connections, cancellation, late-loaded voices, and persistence are covered by `bun run test:voice` and the backend contract harness.

`node scripts/check-phone-sequence.mjs` uses the same installed Playwright and Chromium to check the real notification animation at mobile and desktop widths, including Replay, Show all, exact-message navigation, host CSS isolation, and reduced-motion settings. Put Bun on `PATH`; the script bundles an interactive preview and writes captures to ignored `tmp/phone-sequence`.

`bun run test:npc-lifecycle` checks immediate NPC generation, leaving Contacts during profile writing, returning to the completed profile with its image, and rejection of late progress events at 390px and 900px. It uses controlled responses and writes captures to ignored `tmp/npc-lifecycle`.

Social layout checks also capture empty/populated profiles and independent Twitter, Instagram, and Tumblr editors. They assert full-width empty profiles, bounded editor spacing, cast/character priority, keyboard disclosure controls, retained expansion through saves, and automatic source-group expansion/restoration during Add Contact searches. Large controlled NPC Banks exercise collapse behavior without user data.

`bun run test:floating-widget` exercises Pocket's real controller against a controlled floating-host contract under CSS zoom. At 390px and 1280px, native geometry and older-host fallback paths both test 70%, 100%, and 130% Lumiverse UI scale, pointer dragging to both edges, preference acknowledgement, reload persistence, and clamping after a live scale change. Captures go to ignored `tmp/floating-widget`; no live preferences are read or written.
